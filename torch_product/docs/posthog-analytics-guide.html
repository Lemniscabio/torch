Torch PostHog Analytics Guide

This document explains how to inspect Torch analytics in PostHog and how the marketing landing page connects to the product app.

Quick Health Check

Start in PostHog's event activity view. Search for the core Torch events and open individual event details to confirm the expected properties are present. 

torch_landing_cta_clicked
torch_app_entered
$pageview
assessment_started
assessment_step_completed
assessment_submitted
assessment_completed
results_viewed
pdf_download_clicked

Expected attribution and context properties:

utm_source: "lemnisca_landing"
utm_medium: "torch_landing_cta"
utm_campaign: "torch_assessment"
cta_location: "hero"
product: "torch"
surface: "product"
app: "torch_app"

Recommended Dashboard

Create a dashboard named Torch Acquisition + Assessment Funnel.

Insight PostHog type Configuration
Landing CTA clicks Trends Event torch_landing_cta_clicked, broken down by cta_location.
Product entries from landing Trends Event torch_app_entered, filter utm_source = lemnisca_landing, breakdown by cta_location.
Main assessment conversion Funnel Use the funnel sequence listed below. Filter by utm_campaign = torch_assessment and break down by cta_location.
Assessment friction Trends Event assessment_validation_failed, broken down by step fields such as step_slug.
Result distribution Trends or table Event assessment_completed, broken down by highest_risk, primary_bottleneck, scale_ratio_bucket, organism_class, or process_type.

Main Funnel

This is the most useful first view because it answers which landing CTA brought users into Torch and whether those users completed the assessment. 

torch_landing_cta_clicked
-> torch_app_entered
-> assessment_started
-> assessment_step_completed
-> assessment_submitted
-> assessment_completed
-> results_viewed

Session Replay Workflow

Use session replays after the dashboard shows a drop-off or friction point. Filter recordings by assessment_started, assessment_validation_failed, or users who entered the funnel but did not reach assessment_completed.

Marketing-to-Product Contract

The main landing repo owns outbound CTA attribution. Torch owns reading and storing that attribution, then attaching it to product events. 

https://torch.lemnisca.bio/assess/?utm_source=lemnisca_landing&utm_medium=torch_landing_cta&utm_campaign=torch_assessment&cta_location=hero

For future Lemnisca products, add UTM parameters on the marketing side and add product context registration on the product side.
